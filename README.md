# 鉄道運転シミュレータ

TypeScript + Three.js による鉄道運転シミュレータ。**現実の鉄道の仕組みと物理挙動を
可能なかぎり厳密に再現する**ことを目標にしている。

物理・信号コアと、それを実際に運転できるビューア（運転席一人称視点・外部検証視点・
時系列グラフ）まで実装済み。コアは描画に一切依存しない純粋な TypeScript なので、
別のフロントエンドへそのまま載せ替えられる。

## 設計の核

1. **列車を単一質点ではなく多質点系として解く** — 各車両が自分の距離程で勾配・曲率を
   参照し、遊間と 2 段剛性を持つ連結器で結合する。長編成が勾配変化点を通過するときの
   前後衝動が、特別な処理なしに現れる。
2. **粘着を「力の頭打ち」ではなく輪軸の回転自由度として解く** — 各輪軸が独立した回転
   自由度を持ち、クリープ曲線を介して車体と結合する。空転・滑走は不安定現象として自然に
   発生する。
3. **すべての装置を「指令 → 応答遅れ → 実出力」として時間発展させる** — ブレーキシリンダ
   圧のむだ時間と一次遅れ、回生失効と空気ブレーキへの受け渡し、トルク指令のレート制限を
   陽にモデル化する。
4. **音をサンプルではなく装置の仕組みから合成する** — インバータの PWM を音声サンプル
   レートで実際に走らせ、その電圧波形から電磁加振力を求める。サイドバンドもパルスモード
   切替も、個別に作り込まずに波形から出てくる。
5. **制御方式を主回路の作りから解く** — VVVF インバータのほかに、直流直巻電動機を使う
   抵抗制御と電機子チョッパを持つ。直流機では引張力を指令せず、磁化曲線と電機子回路の
   微分方程式を解いた結果として出す。鋸歯状の引張力や渡りのショックはそこから現れる。
6. **車体の揺れと乗客の動きを物理から出す** — 軌道狂いは距離程の関数として持ち、車体は
   2 次系として応答する。吊り革は**減衰振り子**、立っている乗客は**倒立振子 + むだ時間を
   持つ姿勢制御**として別々に解く。同じ加速度でも**変え方**で結果が変わる。

### モバイル（タッチ）操作

指で触る端末（`pointer: coarse`）か、サイドパネルの入らない幅（900px 以下）では、
画面上に運転台が出る。右のパネルの `タッチ運転台` でいつでも入切でき（PC でも試せる）、
選んだ状態は次に開いたときも残る。

実車の運転台と同じツーハンドルで、**左が主幹制御器、右がブレーキ設定器**。
どちらのレバーも縦にドラッグして段を選ぶ。**上ほど強い**で左右を揃えてあり、
力行は上が最大段、ブレーキは上が非常。

| 位置         | 操作                                                        |
| ------------ | ----------------------------------------------------------- |
| 左のレバー   | 力行 `切` – `P1` … 最大段                                   |
| 右のレバー   | ブレーキ `切` – `B1` … 最大段 – `非常`                      |
| 中央（赤）   | 非常ブレーキ（レバーを引くより速い）                        |
| 中央（上段） | 警笛 / 砂撒き / 確認扱い / 保安装置復帰（押している間だけ） |
| 中央（下段） | 戸閉め / 視点（押すたびに巡回）/ ATO / 一時停止 / 設定      |
| 右上の `≡`   | 走行条件・記録・音量・グラフの引き出しを開閉                |

キーボードと画面のレバーは同じ運転台（`apps/debugger/src/input/driverState.ts`）を
握るので、混ぜて使っても食い違わない。キーで入れたノッチはレバーにそのまま出る。

画面が狭いときは、サイドパネルが右からの引き出しになり、キーの凡例と G メータは畳まれ、
HUD は運転に要る行（速度・制限・ノッチ・扉・次の信号／駅など）だけになる。

走行条件は画面右上で選ぶ。**車両**・**天気**・**保安装置**（ATS-P / ATS-SN）・
**先行列車**・**対向列車**・**2 番線から発車**を互いに独立に選べる
（4 × 4 × 2 × 2 × 2 × 2 = 256 通り）。
選んだ条件からシナリオをその場で組み立てるので、任意の組み合わせがそのまま試せる。
選択肢はデータ側（`packages/data/src/run.ts`）が持つ。

**車両**を変えると同じ路線を 4 種類の制御方式（VVVF / 抵抗制御 / 電機子チョッパ /
音階インバータ）で運転できる。音階インバータは走行性能が既定の VVVF 車と同じで、
変調の諸元だけが違う。

## 物理モデルの要点

**軌道線形とカント** — 平面線形は曲率プロファイル κ(s) で定義し、方位角・座標を数値
積分する。縦断線形は勾配プロファイルの積分。カントは緩和曲線区間で逓減し、非平衡横
加速度と均衡カントは `a = v²κ·cosφ − g·sinφ` のような厳密な三角関数の関係で扱う
（慣用式 `C = GV²/127R` はデータ層の設計則としてのみ使う）。

**列車ダイナミクスと粘着** — 車両は位置・速度、輪軸は角速度を状態に持つ。クリープ力は
すべり率に急峻なため輪軸は後退オイラー法をニュートン反復で解く。軸重は台車間・台車内の
荷重移動を考慮し、どの軸から空転するかを決める。粘着はすべり率に対しピークを持つ
クリープ曲線で表し、ピークを越えると力が落ちる形が空転・滑走を不安定現象にする。

**停止と保持** — 機械ブレーキはクーロン摩擦なので、固着（静止摩擦）と滑りを陽に解く。
1 軸が受け持てる長手力の範囲は輪軸のつり合いと粘着限界で決まり、勾配や連結器の外力を
打ち消す値がその範囲に収まっていれば列車は動かない。結果として停止の瞬間に減速度が
段差で消え、これが乗客の揺り戻しになる。

**曲線通過とアタック角、軋み音** — 台車の 2 本の輪軸は曲線で同時に半径方向を向けられ
ないため、曲率ぶんと通り狂いぶんのアタック角が生じる。これが横クリープの飽和すべり角を
越えると μ の傾きが負になり、車輪の面外振動が自励して曲線の軋み音になる。分岐器のリード
曲線も同じ経路で扱うため、特別扱いなしに鳴る／鳴らないが決まる。

**車体の動揺と乗客** — 軌道狂いは距離程の関数として波長の異なる正弦波の重ね合わせで
生成し、車体各自由度（ロール・ピッチ・ヨー・左右・上下）は固有振動数と減衰比を持つ 2 次
系として応答する。乗客が感じる比力は、カントと車体ロールの両方で傾いた床の座標系へ
水平面の比力を射影して求める。吊り革は**減衰振り子**（物なので加速度に遅れて追従するだけ）
だが、立っている**人**は倒立振子 + 0.14 秒のむだ時間を持つ姿勢制御として別に解く —
ゆっくりした加速度変化にはよりかかって耐えられるが、急な変化には取り残されてよろける。
支持基底面を越えると外挿重心（Hof）を使って踏み出しを判定する。

**分岐器** — 線形（分岐側はリード曲線へ入り、緩和曲線もカントも無い）・揺れ（トングレール
先端とクロッシングを局所的な軌道狂いとして扱う）・音の 3 つの側面で効く。寸法・制限速度・
ATS-P 地上子は番数から自動生成される。

**橋りょう** — 橋の上で音が変わるのは「橋だから」ではなく、**車輪が叩いた力の逃げ場が
変わるから**である。土路盤なら道床と路盤に吸われる力が、橋では桁という薄い板へ入って
面外に振動し、空気を押す。したがって音は

加振力（速度で決まる） × 桁へ届く割合（道床の有無） × 板の動きやすさ × 放射効率

の積になり、4 つとも桁の寸法から出る。板の曲げモードは `f ∝ t / a²` なので、腹板の大きい
上路プレートガーダー橋は 60〜250Hz の「ゴー」、床組の板が小さい下路トラス橋は
150〜600Hz の甲高い音になる。板の動きやすさ（駆動点モビリティ `Y ∝ 1/ρc t²`）は板厚の
2 乗に反比例するので、厚さ 250mm のコンクリート床版は 12mm の鋼板より 2 桁動かない —
コンクリート橋が静かな理由は減衰でも道床でもなく、**そもそも動かない**ことである。
音の大小を作り分けているのではなく、寸法を変えた結果としてこうなる。

**踏切** — 3 つの側面を持つ。**踏切板の目地**（道路の幅がそのまま目地の間隔になる）、
**舗装との段差**（局所的な軌道狂いとして車体を突き上げる）、そして**警報音**である。
警報音は踏切のスピーカから**道路へ向けて**鳴っている音を通りすがりに聞くだけなので、
聞こえ方は位置関係だけで決まる — 距離に反比例する音量、遠いほど高域が失われる空気の
吸収、そしてドップラー効果。音源は静止していて自分が動いているので、式は音源が動く場合
（`f c/(c−v)`）ではなく観測者が動く場合の `f (1 + v_r/c)` になる。警報機は踏切道の両側に
1 台ずつ建っているため、渡っている最中は**片方が近づき、もう片方が遠ざかっている**。
鳴動と遮断桿は時間発展を持つ装置（`LevelCrossingSystem`）で、対向列車が来れば自分が
止まっていても鳴る。

**車体の遮音** — 運転士は閉じた箱の中にいる。走行装置の音（主回路・歯車・転動音・
継目・橋）は床下や台車から構造を伝わって入るので、はじめから車内で聞こえる大きさとして
較正してある。一方、踏切の警報音と対向列車の音は**車外の空気を伝わってくる**ので、窓と
車体を透過するぶんだけ削られる。透過損失は質量則に従って周波数が 2 倍になるごとに 6dB
増えるため、外の音は小さくなるだけでなく**こもる**。屋外では走行音よりよほど大きい警報音
（1m で 90dB 級）が、運転台では走行音より 10dB ほど下に聞こえるのはこのためで、窓を開けた
ときと閉めたときで音量だけでなく音色まで変わるのも同じ理由による。

対向列車の音は**同じ壁を 2 回**通る。各音源の音量は自分の運転台で聞こえる大きさで
揃えてあるが、同じ装置を車外で聞けばもっと大きい（自分の車体が遮っているぶんだけ）。
相手はその車外の音量で放射しており、それがこちらの車体でもう一度遮られて届く。
低い音では 2 つがほぼ相殺し、高い音では質量則の傾きだけが残る。すれ違う列車が
「自分の走行音と同じくらいの大きさなのに、明らかにこもって聞こえる」のはこの非対称の
ためで、音量を下げるだけでは同じようには聞こえない。ただし**すれ違いの圧力波はこの
経路を通らない** — 空気の音として窓を透過するのではなく、車体そのものを押すからである
（音はこもっているのに衝撃だけは体に来る）。

**すれ違い** — 単線なので対向列車と行き違えるのは交換設備の中だけである。隣の線路が
どこにあるかは分岐器の寸法から決まる（`R(1−cosα)` を 2 回と護輪軌条部で 3.38m 横へ寄る）。
至近距離を逆向きに走り抜けるので、先頭がすれ違う瞬間の圧力波（動圧なので**相対速度の
2 乗**）、並んでいるあいだ（相手の編成長 ÷ 相対速度）の走行音、最後尾が抜けるときの
逆向きの圧力波、が続けて来る。

**ダイヤ列車も自列車と同じ装置で走る。** ダイヤが持っているのは時刻に対する位置の
折れ線だけだが、音はノッチ・ゲート・BC 圧から出る。そこで `RemoteTrain` は**位置から
装置の状態を逆に求める** — ダイヤの位置と速度を `TrainDynamics` へ直接書き込み
（積分はしない。位置を決めるのはダイヤであって装置ではない）、そこから
`M a + R_走行 + R_曲線 − F_勾配` でダイヤどおりに走るのに要る力を出し、その力を出す
ノッチを選んで、**実物とまったく同じ** `TractionSystem` / `ElectroPneumaticBrakeSystem` /
`DoorSystem` / `AirCompressor` を回す。ノッチの選び方も運転士と同じで、制動側は減速度と
ノッチの対応表から、力行側はいま出ている引張力を測って必要な指令率を逆算する。

出てきた状態は自列車と同じ合成器（`TrainNoiseSynth` をもう 1 つ）へそのまま渡る。
したがって相手が力行していればインバータの磁気音が鳴り、ブレーキを掛けていれば空気の
音がし、駅に止まっていれば戸閉めのチャイムが鳴る — 音源ごとに場合分けする必要が無い。
継目や分岐器も同じで、相手の軸が実際に踏んだ位置と時刻から自列車と同じ手続きで鳴らす
（継目は線路の側にあるものなので、誰の軸が踏んでも同じ継目が鳴る）。

違うのは**そこから耳へ届くまで**だけである。相手の合成器の出力は、距離 `r/c` の
遅延線を通り、空気の吸収を受け、車体を透過して混ざる。ここで遅延の長さを距離どおりに
動かすと、**すべての音源にドップラー効果が同時に掛かる** — 音源ごとに周波数を掛け直す
必要は無く、これは近似ではなくドップラー効果の定義（波面が届く時刻のずれ）そのものである。
真横を過ぎる瞬間に距離の変化率が 0 になり、そこで音程が元へ戻ることも自然に出る。
効くのは相対速度なので、**自分が止まっていても相手が速ければ大きく変わる**。

**駆動方式** — VVVF・抵抗制御・電機子チョッパを `TractionSystem` の別実装として持つ。
直流直巻電動機はトルク・回転数を諸元として与えず、磁化曲線と電機子回路の微分方程式の
解として従属的に出す。抵抗制御はカム軸進段のたびに電流が跳ね上がる鋸歯状の引張力、
組替え時の渡りのショックが自然に現れる。電機子チョッパは通流率制御で同じ電動機を
段なしで滑らかに回す。

**ブレーキ** — ノッチ → 指令減速度 → 応荷重制御 → 空気ブレーキ指令の先込め →
BC 圧のむだ時間・一次遅れ → 摩擦材の μ(v) という経路で、残りを電気ブレーキが受け持つ。
滑走を検知した車の BC 圧を素早く抜き、収まったらゆっくり込め直す。

**客用扉** — 戸閉連動（全扉が閉まり切って施錠されるまで力行できない）と閉扉予告
（閉指令 → チャイム → 少し置いて動き出し）を時間発展として持つ。

**走行音** — 音源ファイルは使わず、装置の仕組みから波形を合成する
（`packages/audio/`）。インバータは PWM 波形 → 磁束 → 電磁力（マクスウェル応力）→
構造共振 → 放射効率という経路で音を作るため、サイドバンドや同期モードへの移行は
個別に作り込まずに現れる。直流機は加振の**次数**を分けて持つ — 電機子スロット（電磁音・
電流²で鳴る）、通風ファンの翼（空気伝搬・電流に依らないので惰行でも残る）、整流子片
（次数が 3 倍高く、音程ではなくかすれとして乗る）。音程を決めるのは次数の低いほうで、
歯車のかみ合いと合わせて 1 オクターブ幅に収まる。レール継目・分岐器・橋りょう・踏切の
警報音・対向列車とのすれ違い・曲線の軋み音・客用扉・保安装置の報知音・警笛なども
同様に物理量から駆動する。

継目の音は**種類で違う**。定尺の突合せ継目は段差と折れ角をそのまま踏むので低域まで
鳴る（ガタン）が、分岐器の前後に入る絶縁継目は遊間が樹脂で埋まっていて段差が無いので
高い当たりだけ（タン）、橋の両端の伸縮継目はレール端が斜めに削いであって踏むのではなく
乗り移るので擦れる音（シャッ）になる。**ロングレール区間でも橋と分岐器の前後だけ音が
する**のは、そこに実際にその継目が置かれているからで、継目の無い区間に音を足している
のではない。

**保安装置** — ATS-SN（ロング地上子で警報・直下地上子で即時非常）、ATS-P（車上パターン
生成による連続照査）、ATC（段階式・デジタル式）、EB 装置を実装。

**自動運転（ATO / TASC）** — `packages/core/src/operation/autoDrive.ts`。運転士の代わりに
`ControlInput` を組み立てるだけの装置で、物理にも保安装置にも手を入れない。目標に届くのに
必要な減速度を先読みして対応するノッチを選び、勾配・走行抵抗を打ち消してから指令し、
停止直前は減速度そのものを絞ることで衝撃を小さく抑える。

余裕を厚く取って安全を買うのではなく、**先読みの精度で買う**という組み立てにしてある。
制限速度へは速度制限だけでなく**目標までの平均勾配**を織り込んで寄せ（路線の勾配を
頭に入れている運転士と同じ扱い）、目標速度に届いたあとは走行抵抗と釣り合う力行ノッチで
制限の直下を保つ。ブレーキの効きは指令に対する実測比として推定し、**指令より強く効く
条件**（降雪で回生が失効し空気ブレーキが受け持つときなど）でも狙いどおりの減速度になる
よう補正する。これが無いと停止位置のはるか手前で速度を失い、残りを這って詰めることになる。

ハンドルの運び方も運転士に倣う。行き先が決まっているノッチ（発進・再力行・抜き取り）は
ためらわずに運び、制限直下を保っている最中の微調整だけ間隔をおく。**ブレーキが抜け切る
までは力行を立ち上げない**のも同じ理屈で、込めたまま引張力を育てると抜けた瞬間に
そのぶんが加速度として出て、発車のたびに立っている乗客がたたらを踏むことになる。

**速度制限** — 制限速度は先頭端の 1 点ではなく列車の**在線範囲**（最後部〜先頭端）で
引き、最も低い値を採る。制限は最後部が抜けるまで解けない（`Simulation.currentSpeedLimit`）。

**決定論** — コアは `Date.now()` も `Math.random()` も使わない。乱数はシード付き
mulberry32、時刻は引数で渡し未消化時間を整数マイクロ秒で保持するため、`step()` の呼び出し
間隔（フレームレート）を変えても結果がビット単位で一致する。

## データ形式

路線・車両・シナリオは zod スキーマで定義し、現場で使われる単位（km/h・‰・mm・t・
kgf/t・kPa・km/h/s）で書く。コンパイラが SI へ変換し、曲線の制限速度・分岐器の寸法と
制限速度・ATS 地上子・閉塞区間・直流機の磁束定数・抵抗制御の進段表などを自動生成する。
経験式の係数はコードに埋めず、すべてデータ側のパラメータとして持つ。

車両データの主回路は `kind`（`vvvf` / `resistor` / `chopper`）による判別可能ユニオンで、
方式ごとに諸元がまるで違うため既定値は持たせない。

同梱サンプル: 架空の試験線（8km、R600/R400 曲線、25‰ 上り・33‰ 下り、トンネル、
駅 3 — うち起点駅は #12 分岐器 2 基の**交換可能駅**（単線なので対向列車とすれ違えるのは
ここだけ）、閉塞信号 8、側線と保守基地への分岐器、橋りょう 4・踏切 3）と、
同じ路線を走る 4 種類の 4 両編成（VVVF・抵抗制御・電機子チョッパ・音階インバータ）。

橋りょうは桁の作りを 4 通りに変えてある（無道床プレートガーダー・下路トラス・有道床
コンクリート桁・有道床プレートガーダー）ので、同じ「橋」でも音がまるで違うことを聴き
比べられる。ロングレール区間（2600〜4300m）の中に橋りょうと分岐器と踏切を置いてあり、
継目の無い区間で伸縮継目・絶縁継目・踏切板の目地だけが鳴るのが聞き分けられる。
分岐器の先は開通方向で線形が変わるため、試験線は 1 番線・2 番線 2 本の路線データとして
持つ（`buildTestLine(loop)` が共通部分から両方を組み立てる）。

新しい路線を足すには `packages/data/src/assets/` に定義を書き、
`createDefaultLibrary()` へ登録する。

## 検証

`npm test` で 570 件超のテストが走る。主な観点:

- **解析解との突き合わせ** — 惰行減速の常微分方程式、勾配・引張力のみの加速度、曲線抵抗、
  円曲線/クロソイド/縦曲線の線形、ATS-P パターンの厳密解など
- **現象テスト** — 空転・滑走と再粘着制御、電空協調の受け渡し、信号現示の連動、
  速度制限の在線判定など
- **駆動方式** — 直流直巻機の電力保存（`E·I = T·ω`）、抵抗制御の進段・渡り、
  発電ブレーキとチョッパ回生の違いなど
- **客用扉・分岐器・橋りょう・踏切・自動運転・乗客モデル（吊り革／立っている人）・
  走行音**（node でオフラインレンダしてスペクトルを測定）についても、それぞれ物理的な
  整合性を確認する回帰テストを持つ。板の曲げモードが板厚に比例し寸法の 2 乗に反比例
  すること、踏切の警報音が通過の前後で `f (1 ± v/c)` だけ動くこと、すれ違いの圧力波が
  相対速度の 2 乗で効くこと、車体の遮音が質量則どおり 1 オクターブあたり 6dB であること、
  ダイヤ列車の装置が位置だけから復元されて自列車と同じ歯車周波数を出すこと、伝搬遅延の
  伸縮だけで対向列車の音程が `f (1 ± v/c)` だけ動くこと、といった関係を数値で確かめる
- **性質テスト** — 同一入力・異なるフレームレートでの状態ハッシュ一致、記録再生の
  決定論性など

`npm run bench` の実測では、4 両編成（16 軸）を物理 1kHz・装置制御 100Hz で回して
リアルタイム比約 100 倍。

## ビューア

- **運転席一人称視点** — 実物の運転士の目の位置にカメラを置き、車体動揺をそのまま反映する
  （補間しない）。内装はカメラの子として取り付けてあるため、「内装は静止し窓の外だけ揺れる」。
- **外部視点**（追跡・側面・俯瞰・自由）— 列車と線路の関係を確かめる検証用。
- **実寸の構造物** — レール・まくらぎ・道床・架線・信号機・ホーム・車両を、日本の在来線
  （狭軌 1067mm・直流 1500V・20m 級通勤形）の実寸から組み立てる。寸法は
  `apps/debugger/src/render/dimensions.ts` に出典つきで集約されている。テクスチャも
  画像ファイルを使わずすべて手続き生成し、実寸で貼る。
- **昼間の沿線景観** — グラデーションの空、樹木・建物（決定論的配置）、トンネル覆工と照明、
  橋りょう（形式ごとの桁・橋脚・谷と水面）、踏切（遮断桿と交互に閃く警報灯）。
  無道床橋の上では道床が途切れ、まくらぎが桁へ直接乗る — 音が変わる理由がそのまま見える。
- **ダイヤ列車** — 先行列車は同じ線路の前方に、対向列車は交換設備の隣の線路に描かれる。
- **天気** — 走行条件で選んだ天気が絵にも出る。空・霧・日射・環境光・降水・路面を
  `apps/debugger/src/render/weather.ts` の 1 か所で決めるのが要点で、粒を降らせるだけでは
  天気にならない（雨の日が暗いのは雨粒ではなく雲のせいで、遠くが霞むのも雲と雨滴の散乱に
  よる）。降水はカメラを中心とした箱の中の粒を巻き戻して描くので、世界に対しては静止した
  格子として振る舞い、走れば勝手に流れる。雨脚は「粒の速度 − 列車の速度」の向きへ倒れ、
  止まれば真下、飛ばせば長い尾を引く。位置は頂点シェーダの中だけで動かし、毎フレーム
  頂点を送り直さない。積雪は色を掛けるのではなく下地の模様を外して塗り替える
  （材質の色は模様に掛かるので、緑の草に白を掛けても白くはならない）。
- **加速度メータ** — 吊り革の振れと乗客の支持余裕を重ねた振れ盤、車体断面の前面図、
  ピッチングを示す側面図。数値ではなく「乗客がどちらへどれだけ振られているか」を直接見せる。
- **時系列グラフ** — 速度・制限・ATS-P パターン、ノッチ、引張力と電空の分担、主回路
  （制御方式で系列が入れ替わる）、体感加速度と車体ロールなど。
- **走行音** — 主回路・主電動機・歯車・転動音・客用扉・レール継目・分岐器・橋りょう・
  踏切の警報音・対向列車とのすれ違い・曲線の軋み音・ブレーキ・空気・補機・風切り・
  トンネルと橋の反響。車外の音（踏切・対向列車）は車体の遮音を通って入るので、
  屋外での大きさではなく**運転台で聞こえる大きさ**になる。対向列車はこれらすべてを
  自列車と同じ合成器で鳴らすので、相手がどんな状態でも音が付いてくる。
  ミキサのレベルメータは混ざる前の実効値。
  タブを背面に回してもシミュレーションは止まらない（音声を親時計に切り替える）。
- **自動運転** — `O` で入切。装置の動作モードと要求減速度・指令減速度を HUD に出す。

入力は `apps/debugger/src/input/` — `driverState.ts` が DOM に触らない運転台の
状態機械、`keyboard.ts` がキーの対応表、`ui/touchConsole.ts` が画面上の操作盤。
ノッチの進め方は `driverState.ts` だけが持つ。
